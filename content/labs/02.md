## The question
How much can you defend about a function from its instructions and artifacts? Begin with reference functions whose results are known; then make and test hypotheses about compilation, linking, and memory access.

```sh
python3 labs/check.py --lab 2
cc -std=c17 -O0 -g -S labs/02-machine/compute.c -o compute-O0.s
cc -std=c17 -O2 -g -S labs/02-machine/compute.c -o compute-O2.s
cc -std=c17 -g labs/02-machine/main.c labs/02-machine/compute.c -o machine
```

## Annotate the evidence
1. For `sum_words`, identify argument locations, zero-count behavior, element stride, loop edge, and return value. The source deliberately uses unsigned modular arithmetic so reassociation preserves its intended integer result.
2. Compare `signed_min` and `unsigned_min` on a high-bit pattern. Identify signed/unsigned conditions where the generated code exposes them. Preserve ambiguity when an optimization hides source structure.
3. Enter the program with GDB or LLDB, stop in a function, and align source arguments with register/memory values. Debugger launch may depend on your environment's local permissions; assembly inspection remains available without it.

## Locate a missing definition
Compile only `main.c` with `-c`, then try to link that object without `compute.c`. Record the unresolved names. On Linux, inspect symbols and relocations with `readelf` and `objdump`. Add the missing defining object and explain both the failure and repair. macOS requires Mach-O tools or a Linux learning environment for the exact ELF inspection track.

## Investigate a deliberately bad bound
The separate `bounds-bug.c` is intentionally unsafe for index 4. Run it only as this local diagnostic exercise, with instrumentation:

```sh
python3 labs/check.py --lab 2 --sanitize
```

Read the access site, allocation stack, and position relative to the allocation. In a scratch copy, repair the bound and test indices 0, 3, 4, invalid text, and negative input. The parser's maximum of 100 does not match the allocation's four elements. Deleting the write does not implement the intended indexed update.

## Deliverables
Provide an annotated assembly fragment, one link-error explanation, a sanitizer diagnosis, the corrected source, and boundary test evidence. Distinguish the observed fault/report from the contract violation that caused it. Include the native architecture and ABI; do not claim an AArch64 result matches the x86-64 teaching snippet instruction for instruction.

::: solution Investigation guidance
A valid repair rejects indices outside `[0,4)` before access and handles parse errors. The allocation's bound, not the input parser's arbitrary upper number, determines legal indexing. The link repair supplies a definition with the intended external linkage; changing header punctuation does not supply missing machine code. An optimized loop can differ radically from the source-shaped version while preserving its contract.
:::

## Depth extension
Create a nested call that must preserve a value across the call. Inspect how the compiler fulfills the ABI at `-O0` and `-O2`. Then change record layout and measure how stride and offsets change. Explain the artifact evidence without asserting original field names that no artifact contains.
