## Static and shared are different promises
A static archive is a collection of object files. A traditional linker selects archive members needed to satisfy unresolved references at the point where it processes that archive. Input order can therefore matter: objects that need functions typically come before archives that provide them. Linker grouping options exist for circular dependencies, but redesigning the dependency is often clearer. [[ld]]

A shared library is loaded into the process at runtime rather than copied into every executable in the same way. The executable records dependencies and enough metadata for the loader to complete the runtime arrangement. Build success proves that the build environment satisfied its part of the contract, not that a different machine will.

## An executable is not a running process
On Linux, launching a dynamic ELF executable involves the kernel and its designated interpreter/loader. The loader locates shared objects, maps them, performs required relocations, and arranges initialization before ordinary application execution. The `ld.so` manual documents search paths and diagnostic environment settings. [[loader]]

For a binary you built yourself, try `LD_DEBUG=libs ./demo` on a suitable glibc Linux system. Observe which directories and filenames are considered. This is a diagnostic for a known program, not a guarantee that every Linux libc uses the same diagnostics. macOS uses its own loader and `dyld` conventions.

Avoid solving a deployment problem by copying an arbitrary library with the same filename. ABI compatibility includes symbol availability and versioning, layouts, calling conventions, and assumptions made by both sides. A filename match is weak evidence.

## Observe mappings without overclaiming
A Linux process's `/proc/PID/maps` lists virtual ranges, permissions, offsets, and mapped files. Compare an executable's mappings with a shared object's mappings. Read-only code pages may be shareable across processes, while writable data and private copies behave differently. The mapping listing alone does not prove a page is resident in RAM or unique to that process. [[maps]]

Address-space layout randomization means absolute addresses may change between runs. Compare relationships and symbol-relative offsets instead of assuming a debugger address is a stable identifier for future executions.

::: deep Lazy work and indirection
A procedure linkage table and global offset table are part of common ELF mechanisms for indirect dynamic references. Some configurations resolve calls lazily; others resolve eagerly. Security settings, toolchain options, and loader implementations alter the details. The useful invariant is that an external reference needs a well-defined target at the moment it is used.

Distinguish symbol interposition from static lexical scope: a loader can sometimes select among external definitions in ways that surprise someone reasoning only from source file order. Keep interfaces narrow and avoid relying on accidental process-global symbol collisions.
:::

## Retrieve before looking
You move a working binary into a minimal Linux image. It now fails before printing from `main`. List the evidence you would collect before editing the application logic.

::: solution Worked feedback
Collect the exact launch error, executable format/architecture, ELF interpreter path, required shared objects, and the runtime's available loader/libraries. Use `readelf` on the known binary and loader diagnostics where applicable. Missing interpreter, wrong architecture, and missing dependency are different hypotheses. A `main` breakpoint that never triggers supports a pre-application failure, but does not by itself identify which one.
:::
