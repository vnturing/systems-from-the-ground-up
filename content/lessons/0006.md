## Width changes arithmetic
An unsigned `w`-bit type computes modulo `2^w`. In an eight-bit mathematical model, `250 + 13 = 7` after reduction modulo 256. Signed two's-complement interpretation assigns the top bit weight `-2^(w-1)`. Thus `0xF2`, interpreted at eight bits, is `-128 + 64 + 32 + 16 + 2 = -14`.

Do not transfer the unsigned wrap rule to signed C addition. Under our C17 contract, an unrepresentable signed result is undefined behavior. An ordinary processor instruction may produce low bits, but a C compiler's legal reasoning is not defined by that one observation. Selected signed overflow checks can be instrumented with UBSan. [[ubsan]]

## Promotions happen before storage
Consider `unsigned char a = 250, b = 13;`. On our target, `a + b` is evaluated as `int`, yielding 263; assigning back to `unsigned char` reduces the value to 7. An eight-bit destination does not imply eight-bit intermediate arithmetic.

Likewise, mixed comparisons can convert a negative integer into an unsigned value. On ordinary targets, `-1 < (size_t)1` is false because the converted negative value is large. Do not fix this by guessing at casts. Establish whether negative inputs are permitted, reject them when inappropriate, and compare values in a type that represents the valid domain. Consult the conversion rules in §6.3.1. [[c]]

## A real failure: undersized allocation
Suppose an input supplies an element count and each element needs 24 bytes. This is unsafe:

```c
void *p = malloc(n * 24);
```

If `n` is a `size_t`, the multiplication can wrap to a small allocation. A later loop may still attempt to initialize `n` elements. The allocation did exactly what it was asked; the arithmetic was wrong before it ran.

Use a division check, with a nonzero element size:

```c
#include <stdint.h>
#include <stdlib.h>
size_t item_size = 24;
if (n > SIZE_MAX / item_size) {
    /* reject the request */
} else {
    void *p = malloc(n * item_size);
    /* check p, establish ownership, and eventually free */
}
```

This is a pattern, not a complete function: define error reporting and zero-length policy for the calling API. `calloc` performs checked multiplication on the documented Linux implementation; do not substitute an already-overflowed product as one of its arguments. [[malloc]]

::: deep Checked signed addition
For `int a, b`, reject when `b > 0 && a > INT_MAX - b`, or when `b < 0 && a < INT_MIN - b`, before evaluating `a + b`. In these branches the subtractions remain representable. The tempting test `a + b < a` already performs the dangerous operation and fails for negative values.

A right shift of a negative signed value is implementation-defined in the older C contract used here; a left shift has restrictions beyond the shift count. Prefer unsigned values for bit manipulation and keep signed quantities for their mathematical domain. New language revisions can refine representation rules; the course does not silently assume those revisions.
:::

## Retrieve before looking
In a toy unsigned 12-bit size type, the maximum is 4095. An element needs 24 bytes. What is the largest safe count? What allocation size would count 171 produce after modulo reduction?

::: solution Worked feedback
`floor(4095 / 24) = 170`, requiring 4080 bytes. Count 171 mathematically needs 4104 bytes, which reduces to eight modulo 4096. An eight-byte allocation cannot hold 171 elements. The tiny model makes visible the same structural bug that appears with much larger real types.
:::
