## A branch consumes a comparison
In AT&T x86 syntax, `cmpq %rsi, %rdi` sets flags as if `%rdi - %rsi` had been computed, without storing that difference. `je` tests equality. `jl` tests signed less-than; `jb` tests unsigned below. The same operands can produce different branching decisions depending on the interpretation. [[intel]]

Do not read a conditional jump independently of the instruction that last set the flags. An intervening arithmetic instruction can replace them. Annotate both the comparison and the branch edge.

## Build a basic-block graph
Consider an illustrative loop over 32-bit integers with count in `%rsi`:

```asm
xorl %eax, %eax
xorl %ecx, %ecx
.Ltest:
    cmpq %rsi, %rcx
    jae .Ldone
    addl (%rdi,%rcx,4), %eax
    incq %rcx
    jmp .Ltest
.Ldone:
    ret
```

The setup initializes the sum and index to zero. The test exits when the unsigned index is at least the count. The body loads an indexed integer, adds it, increments the index, and returns to the test. A useful invariant is “before the test at index `i`, the accumulator contains the low 32 bits of the sum of elements before `i`.”

For a C interpretation using signed `int` addition, you must additionally constrain inputs so the sum is representable. Machine-level low-bit addition alone cannot tell you whether the original source was signed, unsigned, or produced under a special overflow flag.

## Source structure is not preserved
A compiler may rotate a loop so the test is at the bottom, replace a branch with a conditional move, unroll several iterations, or eliminate an entire computation. Find the entry edge, back edge, and exit edge. Then ask which values change at each edge. Do not insist on seeing a familiar `for` layout.

A conditional move can remove a branch penalty but may calculate both candidate values. Whether it is beneficial depends on data dependencies, instruction costs, and predictability. Compiler optimization decisions are target- and version-dependent. [[opt]]

::: deep Signedness leaves clues, not complete types
The use of `jb` suggests an unsigned comparison at that point; it does not prove the original variable had a particular typedef. Compilers can transform comparisons while preserving all valid source behaviors. Similarly, a test against zero may combine several source conditions.

To recover a function, generate candidate source, compile it under matching flags, and compare the value flow. Equivalent behavior is a stronger goal than identical instruction spelling. Optimization, compiler version, and target features can all change the spelling while preserving the contract.
:::

## Retrieve before looking
Trace the loop with count zero. Then trace count three and elements `{5, 7, 2}`. Which instruction first prevents the zero-count memory access?

::: solution Worked feedback
At count zero, index zero satisfies `index >= count`; `jae` jumps directly to return and the result remains zero. For count three, the successive sums are 5, 12, and 14. The comparison and `jae` edge guard the load. A loop written with an unconditional first load would need a separate empty-input guard.
:::
