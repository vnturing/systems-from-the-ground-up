## Draw objects before addresses
An object is a region of storage with a lifetime and a type. A pointer value can designate an object, but does not carry a universal permission to read whatever numerical address happens to follow it.

```c
int a[4] = {12, 25, 31, 48};
int *p = &a[1];
int x = *p;
p[1] = 99;
```

Draw four adjacent integer boxes. `&a[1]` produces a pointer to the second element. `*p` reads that element, so `x` becomes 25. `p[1]` means `*(p + 1)` and designates the third element of the original array, so it becomes 99. Pointer arithmetic advances by elements, not bytes: if `sizeof(int)` is 4 on this implementation, adding one advances by four bytes.

This statement describes the chosen implementation, not a universal C guarantee that every `int` has four bytes. The pointer and array rules live in §§6.3.2.1 and 6.5.6 of the draft. [[c]]

## A bound is part of the interface
An array argument usually becomes a pointer to its first element. That conversion loses the array length. Inside `void inspect(int a[])`, the parameter behaves as a pointer; `sizeof a` measures that pointer, not the original array. Therefore an API must pass a count, a sentinel with a clear contract, or another representation of the bound.

Inside the scope that actually declares `int a[4]`, `sizeof a / sizeof a[0]` computes the element count. It works because `sizeof a` still measures the array. Memorizing the formula without its scope condition creates subtle bugs.

A pointer one past the final element may be formed for iteration and comparison within the same array. It must not be dereferenced. Moving still farther is not a valid way to explore nearby memory. An address that looks plausible is insufficient evidence of a valid C access.

## Strings add a second length
`char name[] = "Ada";` creates four characters, including a terminating zero byte. The text length is three; the array capacity is four. `strlen` needs a reachable terminator and does not know the buffer's capacity. A received network byte sequence is not automatically a string.

Use `%zu` for `size_t` and `%p` with an argument converted to `void *` when printing object pointers. For reading object representation, character access or `memcpy` is preferable to casting an arbitrary byte address to a pointer with stricter alignment and type requirements.

::: deep Pointer equality is not ownership
Two pointers can designate the same live integer. Updating through one changes the value observed through the other. But two similar printed addresses at different times do not prove that the same object is alive: allocators can reuse storage. Keep three facts separate in every pointer diagram: the designated object, the allowed range, and the lifetime.

AddressSanitizer can expose many out-of-bounds accesses during a run. Its success on one input does not establish the bounds of all possible calls. Draw the contract first, then use instrumentation to challenge it. [[asan]]
:::

## Retrieve before looking
Let `q = &a[2]` after the earlier writes. What are `q[-1]`, `*q`, and `q + 2`? Which of these may be read as an integer?

::: solution Worked feedback
`q[-1]` is `a[1]`, or 25. `*q` is `a[2]`, or 99. `q + 2` is one past `a[3]`; you may form that pointer but may not read an integer through it. Negative indexing is not intrinsically invalid: remaining within the original array matters. Try drawing a new array of length three and redoing the bounds.
:::
