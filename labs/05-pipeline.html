Lab 05 · 2–4 hours, with extensions

A pipeline that can finish

Predict. Run. Explain. Preserve the evidence.

Download all lab files ↓ Environment setup

The question

Can you account for every process path and descriptor reference well enough to explain EOF and termination? The reference sends a fixed message through a pipe to tr, waits for the child, and returns failure if the child did not complete successfully.

sh
python3 labs/check.py --lab 5
cc -std=c17 -Wall -Wextra -Wpedantic labs/05-pipeline/pipeline.c -o pipeline
./pipeline

The expected output is SYSTEMS NEED EVIDENCE followed by a newline. A POSIX environment with tr on PATH is required. The design uses a single-threaded parent; it is not a safe template for arbitrary library work after fork in a multithreaded process.

Draw ownership in time

  1. Immediately after pipe creation, draw both descriptors in the parent.
  2. Immediately after fork, draw both descriptors in both processes and connect entries to the same pipe endpoints.
  3. Apply every close and dup2. Mark the child's standard input and standard output, then identify the moment the last writer reference closes.
  4. Follow exec success and failure separately. Explain why the child uses _exit on failure and why the parent decodes wait status before returning.

Controlled failure experiments

In a scratch copy, retain the child's writer endpoint and predict the EOF hang. Run with a timeout so the experiment does not leave a process waiting indefinitely. Restore the close and verify termination. Next replace the executable name with a nonexistent utility; verify a nonzero final result and explain why an exec failure did not create a second child.

Use strace -f on an appropriate Linux machine if available. Compare syscall evidence with the source diagram. The normal-output test intentionally does not assert a particular parent/child scheduling order.

Signal extension

Add a sigaction handler that sets a flag for controlled termination. Keep stdio, allocation, and complex cleanup out of the handler. Explain whether your normal main loop can block despite the flag, and design a mask/wait transition if needed. For multiple children, notifications can coalesce; state and reaping loops must account for all children.

Completion criteria

Provide the descriptor timeline, process tree, expected EOF condition, two controlled failure results, and a corrected shutdown explanation. A demonstration that prints uppercase but leaves a child or writer reference behind is incomplete.

Investigation guidance

The reader needs every writer reference closed, including the accidental writer inherited by the child. A failed exec returns in the same child; _exit(127) makes that failure visible for this example. Parent and child private variables diverge, but inherited descriptors can still refer to shared kernel state. Distinguish those layers when explaining the timeline.

Depth extension

Build a two-child pipeline and specify error propagation if creation of the second child fails. Who closes each already-created endpoint, and who reaps the first child? Handle partial setup as a first-class state rather than appending cleanup after the success path.
