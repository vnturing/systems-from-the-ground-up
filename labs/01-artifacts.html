Lab 01 · 2–3 hours, with extensions

An artifact and representation notebook

Predict. Run. Explain. Preserve the evidence.

Download all lab files ↓ Environment setup

The question

What survives as a fact as you move from source text to bytes? Produce a notebook that separates language guarantees, model assumptions, and observations on your machine. Keep code experiments small enough that you can predict the outcome first.

Start from the reference

Download the lab bundle from the course home, unzip it, and open a terminal in the extracted directory. The bundle contains labs/ at its root. In a repository checkout, use the repository root. Run:

sh
python3 labs/check.py --lab 1
cc -std=c17 -Wall -Wextra -Wpedantic -g labs/01-artifacts/inspect.c -o inspect
./inspect

The checker also retains preprocessed, assembly, and object artifacts under .build/. Open them in a text editor or use an appropriate binary-inspection tool. The reference checks multiplication without intentionally overflowing a signed expression.

Make predictions

  1. Predict the exact four representation bytes of 0x0A1B2C3D under both little- and big-endian order. Compare with your observed machine.
  2. Draw the record fields and padding under a four-byte-int/four-byte-alignment assumption. Compare sizeof, alignment, and offsetof results. Explain any mismatch.
  3. Predict float increment behavior at 2^24 only after recording radix, precision, and evaluation method. Distinguish the IEEE binary32 model from C implementation properties.
  4. Add a complete caller for the positive-sum function in Lesson 02. Test empty input, all negative input, and a small mixed input satisfying the representability precondition.

Change one contract

Replace the safe product calculation in a scratch copy with a deliberately unchecked unsigned product. Feed a count that wraps in a toy 12-bit model rather than attempting to allocate absurd amounts of real memory. Show the mathematical requested size, wrapped size, and resulting mismatch. Do not run a loop that writes past an actual allocation.

Deliverables and completion criteria

Submit a table with prediction, observation, explanation, and portability scope for each experiment. Include tool versions and compile commands. Supply at least one example where the same bits admit two interpretations and one where a plausible pointer is invalid because of lifetime or bounds.

Investigation guidance

The byte sequence is target-dependent; the mathematical value printed in hex is not. Struct layout is ABI-dependent; the requirement that each object meet its alignment is the stable concept. Floating-point spacing depends on format and intermediate evaluation, so a result without those assumptions is incomplete. A correct artifact notebook records surprising observations instead of editing predictions afterward.

Depth extension

Write explicit functions encoding and decoding a four-byte big-endian unsigned integer without casting an input buffer to uint32_t *. Test every single-bit value, zero, and the maximum value. Explain why the implementation does not depend on host byte order or aligned input.

Primary sources

  • GCC — stages of compilation

    Use -E, -S, and -c to stop at different stages; inspect artifacts before blaming the runtime.

  • WG14 N1570 — public C11 committee draft

    Language contracts: §§6.2 (types, lifetime, representation), 6.3 (conversion), 6.5 (expressions), 7.22.3 (allocation), 7.17 (atomics). The labs compile as C17 and use the shared subset; this older draft is not the final C17 standard.

  • David Goldberg — floating-point arithmetic

    Author's paper hosted by Oracle; rounding, cancellation, and numerical error. Work through the reasoning rather than memorizing a tolerance.
