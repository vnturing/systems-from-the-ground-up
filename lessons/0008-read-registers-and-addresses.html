Read registers and addresses

Translate a short x86-64 instruction sequence into value flow.

Choose a syntax and a target

This lesson uses Linux System V AMD64 and AT&T assembly syntax. Source comes before destination, register names start with %, and immediates start with $. Intel syntax reverses the usual operand order and uses different memory notation. Label the syntax before interpreting a snippet.

An architectural register is named machine state. %rax names a 64-bit register, %eax its low 32 bits. On x86-64, writing %eax clears the upper half of %rax; writing a smaller subregister has different effects. A register's bit pattern does not carry the C type that led to it. The instruction establishes how the bits are used. Intel — architecture and optimization manuals

Follow values before guessing source

Consider this illustrative function body for two integer-like inputs:

asm
leaq 8(%rdi,%rsi,4), %rax
movl (%rax), %eax
ret

First compute rdi + 4*rsi + 8 and place that address-like value in %rax. No data load happens during lea. Then load four bytes from the computed address into %eax, clearing the high half of %rax. Finally return. If %rdi points at the beginning of four-byte integers and %rsi holds an index, the address corresponds to element index + 2.

With base address 0x1000 and index 3, the computed address is 0x1014. If four bytes there encode integer 42 in little-endian form, the returned low 32 bits represent 42. The calculation can be correct while the access is invalid if the original array is too short. Assembly arithmetic does not establish the C bounds contract.

Separate instruction classes

A move between registers copies bits. A memory load obtains bits from an address. A store modifies addressed memory. Arithmetic computes a new value; comparison updates condition flags used by later instructions. Start an annotation with these categories instead of trying to reconstruct a whole function at once.

The System V ABI places the first ordinary integer/pointer arguments in %rdi, %rsi, %rdx, %rcx, %r8, %r9; common scalar integer results use %rax. Aggregates, floating-point values, and variadic calls have additional classification rules. Do not extrapolate the simple list to every function signature. x86-64 psABI — official project

The same idea on AArch64

AArch64 commonly passes ordinary integer/pointer arguments in x0 through x7 and returns a simple integer result in x0. Registers w0 through w30 name 32-bit views; writing a w register zeros the upper half of the corresponding x register. Arithmetic and loads are separate instructions in this ISA. Apple platform rules add details beyond the base AAPCS64. Arm — AAPCS64

When your Apple Silicon compiler emits ldr, add, or madd, translate value flow with the same method. Native output is the right evidence for your program. An x86 snippet in a webpage is a labeled example, not the assembly your machine must emit.

Retrieve before looking

For base 0x2000, index 5, and scale 8, what is 16 + base + index*8? Does an LEA-style calculation alone prove the address is readable?

Worked feedback

The result is 0x2038: decimal 16 plus 40 gives offset 56, or hexadecimal 0x38. Computing it does not load memory and does not prove mapping, permissions, object lifetime, or array bounds. If you added hexadecimal digits as decimal, convert the offset separately before adding.

Transfer

Compile the arithmetic functions in Lab 02 with -S -O0 and -S -O2. Annotate inputs, transformations, memory operations, and result. Preserve multiple plausible C interpretations when the instructions do not distinguish them.
