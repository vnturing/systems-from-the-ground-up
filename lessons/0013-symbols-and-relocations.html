Symbols and relocations

Explain how separately compiled references acquire final addresses.

Two jobs at one boundary

A linker resolves names and adjusts references. Symbol resolution answers “which definition satisfies this reference?” Relocation answers “what value or displacement belongs at this site after placement?” Neither requires the linker to reconstruct your original C program.

Make api.h declare int adjust(int);, define adjust in adjust.c, and call it from main.c. Compile the two source files independently with -c, then link the objects together. The calling object can contain machine instructions even while the callee's final location is unknown. GCC's stage controls let you retain that intermediate artifact. GCC — stages of compilation

Inspect the evidence on Linux

Use these commands with your own files:

sh
readelf -s main.o
readelf -r main.o
readelf -S main.o
objdump -dr main.o
cc main.o adjust.o -o demo
readelf -l demo

The symbol table can identify an undefined external name. Relocation entries identify places that depend on symbol placement. Section headers describe linker-oriented divisions such as code and data. Program headers describe loadable segments and other runtime information. Sections and segments answer different questions; a source variable does not correspond one-to-one to a segment. GNU Binutils — readelf

The exact relocation kinds depend on architecture, position independence, and compiler flags. Describe the role of an entry before memorizing its target-specific name.

Linkage is a source-level design choice

A file-scope helper declared static has internal linkage; it is not the same helper name in every translation unit. An extern declaration normally refers to an externally linked definition. Put declarations in a header; place one intended definition in a .c file. Including a header that defines an ordinary global in several translation units can produce multiple-definition failures.

A clean repair uses the intended ownership of the symbol, rather than a linker option that suppresses conflicting definitions. When the same name has incompatible declarations across separately compiled files, a successful link need not establish a sound type contract.

Position independence still requires coordination

A position-independent executable can be loaded at varying bases, supporting address-space randomization. Many references use relative addressing, but some still require tables or loader work. “Position independent” does not mean “there are no relocations.”

On macOS, the object/executable format is Mach-O. otool, nm, and the platform linker provide related evidence with different metadata. Lab 02's C build is portable; its ELF inspection instructions are explicitly a Linux track. Use a Linux VM/container when you need those exact artifacts.

Retrieve before looking

Compilation succeeds for both files; the final link reports an undefined reference to adjust. Name three concrete causes and the artifact you would inspect first.

Worked feedback

The defining object may be missing from the command, the definition may have internal linkage, or its exported name may differ because of a typo or language linkage. Inspect the object symbol tables and the actual link command. Repeating the compile does not address a missing link input. The GNU linker manual explains command-line input processing.
