A program is a trail of evidence

A web framework can hide most of the machine until a bug crosses a boundary. Our starting skill is to locate that boundary. A source file, an object file, an executable file, and a running process are different things. Each is evidence about a different stage. A failed build does not tell you anything about how a process would have run.

Create a file named hello.c in a scratch directory:

c
#include <stdio.h>
int main(void) {
    int count = 3;
    printf("records=%d\n", count);
    return 0;
}

#include makes declarations available. main is the entry function for this hosted C program. Braces delimit its body; a semicolon terminates a statement. printf writes formatted output: %d expects an int. return 0 reports successful termination to the environment. These small contracts matter: the machine does not check that a format string matches the arguments you intended.

Stop the toolchain at each boundary

Run these commands separately; keep the resulting files:

sh
cc -std=c17 -Wall -Wextra -Wpedantic -E hello.c -o hello.i
cc -std=c17 -Wall -Wextra -Wpedantic -S hello.c -o hello.s
cc -std=c17 -Wall -Wextra -Wpedantic -c hello.c -o hello.o
cc hello.o -o hello
./hello

The .i file is preprocessed text; system headers make it much larger than your input. The .s file contains target assembly. The .o file contains machine code and metadata, including references that may remain unresolved. The final command links an executable. The compiler driver coordinates these stages; its name does not mean every error it prints is a compiler error. GCC documents these stopping points explicitly. GCC — stages of compilation

The output should contain records=3. On a POSIX shell, run echo $? immediately afterward to inspect the exit status. This status is a separate channel from printed text. A program can print a reassuring message and still fail.

A diagnostic experiment

Change printf to print_records and add void print_records(const char *, int); above main. Compile with -c: this should succeed because the call has a declaration. Link the object: it should fail because no definition was supplied. Now remove a semicolon: that fails earlier, while translating source. Restore the working program before continuing.

Compiler messages contain locations, notes, and sometimes suggested repairs. Read the first relevant error before chasing later ones: one malformed declaration can generate a cascade. Warnings are evidence worth investigating, not a proof that a warning-free program is correct. GCC — warning options

Why the artifact matters

A source-level change can alter several later artifacts, but the reverse is not unique. Many source expressions can produce the same instructions. A missing header, an unresolved symbol, a loader failure, and a segmentation fault therefore need different investigations. Keep the command, tool version (cc --version), architecture (uname -m), and exact error together. Reproducibility starts before you own a debugger.

On Linux the executable is normally ELF; on macOS it is normally Mach-O. Apple Silicon typically emits AArch64 assembly. This course labels Linux/x86-64 examples and teaches native C experiments alongside them. Different assembly on your Mac is an observation to explain, not a failed lesson.

Retrieve before looking

Without rerunning the commands, name the input and output of each stage. Which artifact could contain an unresolved external reference? Which command would you use to see expanded headers?

Worked feedback

Preprocessing transforms C source and included text into expanded source. Compilation transforms that into assembly; assembly produces a relocatable object. Linking combines objects and libraries into an executable. Use -E for expanded headers and -c for an object without a final link. If you only remembered file suffixes, repeat the missing-definition experiment and explain why compilation can succeed.

Transfer

A binary exists but launching it reports a missing shared library. Write down why inspecting a semicolon in the source is unlikely to be the fastest first move. In Lab 01, retain an artifact notebook rather than just the final output.
