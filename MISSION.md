# Mission: Explain real programs from source code down to hardware

## Why
Learn to explain and debug real programs by connecting C source, compiler output, machine execution, memory, operating-system behavior, and network I/O. Build an evidence-based debugging practice that survives unfamiliar code and unfamiliar machines.

## Success looks like
- Follow a small C program through preprocessing, compilation, assembly, linking, loading, and execution.
- Predict representations, pointer operations, assembly control flow, cache mappings, and virtual-address translations; check predictions with tools.
- Diagnose and repair memory-lifetime, process, I/O, framing, and concurrency bugs using reproducible evidence.
- Build and investigate a bounded network service, explaining correctness and performance across system layers.

## Constraints
- Assume little C experience; provide a progressive C bridge and explicit prerequisites.
- Prefer depth, derivations, experiments, and worked feedback over a superficial overview.
- Original explanations and labs; acknowledge CS:APP as inspiration without reproducing its text, figures, or assignments.
- Static, accessible, printable HTML deployable under a GitHub Pages repository subpath; no paid services or frontend build dependencies.

## Out of scope
- No additional exclusions have been requested. Kernel implementation, compiler construction, distributed consensus, and advanced exploitation are extension paths rather than prerequisites.
