Cache and address-translation models

Keep cache blocks, virtual pages, and live C objects separate.

Cache model

For S sets, E ways, B bytes/line:

QuantityCalculation
Data capacityS E B
Block numberfloor(byte_address / B)
Setblock_number mod S
Tagfloor(block_number / S)
Offsetbyte_address mod B
Average time in the simple serial modelhit_time + miss_rate * additional_miss_penalty

Our simulator starts empty, processes one-byte read addresses, uses LRU replacement, and omits prefetch, writes, multiple levels, coherence, and overlap. It teaches mapping; it is not a hardware performance predictor. Historical practitioner experiments motivate hypotheses for real machines. Ulrich Drepper — What Every Programmer Should Know About Memory

Paging model

For page size P:

QuantityCalculation
VPNfloor(virtual_address / P)
Offsetvirtual_address mod P
Physical addressframe * P + offset, only after mapping/permission checks
Flat page-table entries2^(virtual_bits - log2(P))
Approximate TLB reachentry_count * page_size for the selected structure

The interactive model is a 16-bit virtual address space with configurable power-of-two pages and a toy readable page table. Real tables use architecture-specific formats and multiple levels. Arpaci-Dusseau & Arpaci-Dusseau — Paging: Introduction OSTEP — Faster Translations (TLBs)

Memory accounting distinctions

Requested live bytes, allocator-held bytes, virtual mapped bytes, resident pages, and private dirty pages are different measurements. free can release application ownership while the allocator retains pages. mmap can establish a large virtual range without immediate private residency. A readable mapped page cannot prove an individual C pointer is in bounds or alive. Linux man-pages — malloc(3) Linux man-pages — mmap(2) Linux man-pages — proc_pid_maps(5)
