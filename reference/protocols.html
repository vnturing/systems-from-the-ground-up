Process, I/O, and framing contracts

Progress, ownership, and EOF at each boundary.

Process lifecycle

OperationSuccessFailure / obligation
forkParent receives child PID; child receives zeroNegative return creates no child; clean up acquired state
execReplaces current image; does not return to old codeReturns on failure; controlled child path must terminate appropriately
waitpidCollects child stateHandle interruption/errors; decode status with matching macros
dupAnother descriptor refers to the same open-file descriptionShared offset; close each owned handle

Every process path needs descriptor ownership. Pipe EOF arrives after buffered bytes drain and every writer reference closes. Signals are notifications, not stored counts of every event. Keep asynchronous handlers inside the async-signal-safe contract. Blocking byte-transfer loop

  1. Keep done <= length and a live buffer of the promised capacity.
  2. Request from buffer+done for length-done bytes within interface limits.
  3. Positive result advances progress by the actual count.
  4. EINTR retries under the operation's documented contract.
  5. EOF, no progress, and other errors are classified deliberately.
  6. Nonblocking EAGAIN transfers control to readiness waiting; it is not a busy retry.

Check signed syscall results before unsigned conversion. Do not infer remote processing or persistence from a local write count. Linux man-pages — read(2) Linux man-pages — write(2)

Course frame protocol

FieldContract
HeaderFour bytes, unsigned big-endian payload length
PayloadExactly the declared number of bytes
Length bound0 through 4096 inclusive
TransformationASCII lowercase letters become uppercase; other bytes unchanged
Success responseSame length encoding and transformed payload
Invalid inputClose/reject; no successful response for the invalid frame
EOFClean between frames; truncation inside header or payload

This protocol is original and deliberately small. It is not HTTP. TCP supplies a byte stream, so input chunks may split or combine any frame boundaries. IETF — RFC 9293: TCP IETF — RFC 9112: HTTP/1.1

Shutdown ledger

For each resource, record creator, owner, transfer point, normal release, failure release, and last possible user. Include descriptors, buffers, queue entries, locks, and worker threads. Join users before destroying their synchronization state.
