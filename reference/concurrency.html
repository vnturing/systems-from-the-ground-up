Concurrency invariants

Protect relationships and prove a way to stop.

Bounded queue contract

StateInvariant / transition
Count0 <= count <= capacity under the queue mutex
PutWait while full and open; reject if closed; insert; signal not-empty
TakeWait while empty and open; if closed+empty stop; remove; signal not-full
CloseSet closed under mutex and broadcast so all waiters recheck
DestructionUnlock, join every user, then destroy synchronization objects

A wakeup is not an item reservation. Use while for predicates. pthread_cond_wait releases-and-waits atomically relative to the mutex protocol, then reacquires before returning. POSIX manual — pthread_cond_wait OSTEP — Condition Variables

The C model, platform primitives, and hardware mechanisms are related but separate. Kernel barriers are advanced comparison material, not a substitute for user-space language synchronization. WG14 N1570 — public C11 committee draft Linux kernel — memory barriers

Diagnose progress

Draw a wait-for graph for deadlock. Enforce a consistent lock order. Never join a worker while holding a lock it needs to terminate. Track useful completions to distinguish high CPU activity from useful progress. Consider starvation and fairness separately from deadlock avoidance. OSTEP — Locks

Diagnose scaling

Measure correctness first, then completed jobs/time, latency distribution, queue depth, and resource pressure. Hypotheses include serialized work, lock wait, memory bandwidth, false sharing, and output backpressure. Thread count is an experimental variable, not a guarantee. Brendan Gregg — perf examples Brendan Gregg — the USE method

Instrumentation

Use TSan where supported, in a separate build from ASan. Keep the tested workload and limits of silence explicit. For exactly-once queue checks, use item identities as well as totals; two wrong operations can cancel in a sum. Clang — ThreadSanitizer
